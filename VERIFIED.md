# Zero verification

The v1 checks cover Windows 11 x64 selected-file cleanup and its supported local scheduling environment. They use new disposable files, separate explicit state directories and uniquely identified temporary tasks. Existing user files, keys, profiles and tasks are outside the tests.

The repeatable build checks formatting, unit tests, Clippy, executable version and exact source inputs. `scripts/verify-core.ps1` checks the actual executable with disposable selections, sibling preservation, signed receipt verification and tampering, saved-profile filters and duplicate protection, corrupt-profile preservation, informational commands and the disabled whole-volume command. `BUILD.json` and the paired package manifests tie these checks to the delivered source and executable.

Local release acceptance additionally checks the visible usage/preview dialogs, unchanged previewed bytes, actual Task Scheduler registration and readback, one manually started profile task, a naturally triggered minute agent with a signed request/result, replay prevention, bound-state refusals and removal of the exact test tasks. Package acceptance extracts fresh source and Windows editions and builds the source edition again. Release CI produces another executable with its own digest; the public Windows package is checked separately after download.

These checks verify current logical file operations. They do not establish physical-media erasure, historical-copy removal, cross-machine queue delivery, recurrence across days or reboots, operation while signed out or on battery, or independent forensic certification. The default tasks require a signed-in, awake, AC-powered Windows session. See [storage and recovery](STORAGE_AND_KEY_MODEL.md) and [remote job trust](REMOTE_JOBS.md).

The October 8 acceptance uses 32 unit tests, twelve executable core checks and visible usage/preview inspection. A separate twelve-registration test covers repeated calendar changes. A 64 MiB disposable profile task is stopped while Task Scheduler reports Running, then retried; the selected file had already completed when termination was observed, no pending record remained, and its unrelated sibling stayed unchanged. This checks task termination and retry, rather than a mid-file recovery. The unit suite separately checks recovery after a recorded interruption and refusal of a replaced file identity. The source ZIP is built with Windows PowerShell 5.1, and changed or extra delivery files are refused before extraction.
